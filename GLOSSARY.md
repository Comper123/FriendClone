# Глоссарий

Термины проекта в порядке прохождения данных через код. Новые термины добавляются сюда по мере появления.

## Данные

| Термин | Что это | Где в коде |
|---|---|---|
| **сообщение** | одна запись из экспорта Telegram | элемент `clear_chat` |
| **ход** (turn) | несколько подряд идущих сообщений одного автора, склеенных вместе | результат `group_turns` |
| **пара** (pair) | «что было до» плюс «ответ друга» | результат `build_pairs` |
| **контекст** (context) | ходы, которые шли перед ответом | `pair["context"]` (список словарей) |
| **prompt** | тот же контекст, но склеенный в одну строку с метками `я:` / `он:` | результат `format_pair` |
| **reply** | ответ друга, строка | `pair["reply"]` |

Контекст и prompt это одно и то же в двух формах: список ходов и строка.

## Токенизация

| Термин | Что это |
|---|---|
| **токен** | минимальная единица, которую видит модель. У нас это один символ |
| **словарь** (vocab) | все токены, которые модель знает. Размер: `vocab_size` |
| **`stoi` / `itos`** | таблицы «символ → номер» и «номер → символ» |
| **id** | номер токена |
| **служебные токены** | `<SEP>` и `<EOS>`: не символы, а метки границ. Получают отдельные id после всех символов |
| **encode** | превратить строку в список id |

## Подготовка к обучению

| Термин | Что это |
|---|---|
| **`ids`** | вся последовательность из id: контекст, `<SEP>`, ответ, `<EOS>` |
| **`labels`** | «правильные ответы»: то же, что `ids`, но на ненужных позициях `-100` |
| **маска** (mask) | правило «здесь ошибку не считаем». Технически `-100` в `labels` |
| **сдвиг** (shift) | вход и цель смещены на одну позицию: по токену `t` предсказываем `t+1` |
| **`x`, `y`** | вход модели и цель: `x = ids[:-1]`, `y = labels[1:]` |
| **паддинг** (padding) | добивание коротких последовательностей заглушкой до одной длины |
| **батч** (batch) | несколько примеров, которые модель обрабатывает разом |
| **`block_size`** | максимальная длина последовательности, которую модель видит за раз |

## Обучение

| Термин | Что это |
|---|---|
| **logits** | сырые оценки модели для каждого токена словаря на каждой позиции |
| **loss** | число, показывающее, насколько модель ошиблась. Обучение его уменьшает |
| **cross_entropy** | формула loss для предсказания токена. Пропускает позиции с `-100` |
| **embedding** | таблица, превращающая id в вектор чисел, с которым работает сеть |
| **attention** | механизм, которым токен «смотрит» на другие токены последовательности |
| **train / val** | данные для обучения и данные для проверки, которые модель не видела |
| **epoch** | один полный проход по всем обучающим данным |

## Тензоры

| Термин | Что это |
|---|---|
| **тензор** (tensor) | многомерная таблица чисел, аналог массива NumPy, но с поддержкой GPU и автоматических градиентов |
| **shape** | размеры тензора по каждой оси. У `X` это `(B, T)`: число примеров и длина последовательности |
| **`B`, `T`** | обозначения: `B` число примеров в батче, `T` длина последовательности |
| **dtype** | тип чисел в тензоре. Для id токенов нужен `torch.long` (целые) |
| **collate** | сборка списка примеров в один батч: паддинг и превращение в тензоры |

## Частые путаницы

- **Контекст и `block_size` не одно и то же.** Контекст это то, что мы кладём в пару (последние N ходов). `block_size` это ограничение самой модели по длине. Если строка длиннее, её придётся обрезать.
- **`ids` и `labels` одной длины, а `x` и `y` короче на 1.** Это следствие сдвига.
